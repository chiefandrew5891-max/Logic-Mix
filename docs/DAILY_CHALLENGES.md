## Модель данных (schema 1)
Объект `public/<channel>/v1/daily/<YYYY-MM-DD>/<date>-t<tier>-<lang>.json`: `dailyId, date, tier, language, validFrom/Until (UTC), generatorVersion, verified, puzzles[5]`.
Задание: `id, slot, category, difficulty, seed (<2^63), params, [language, pack{packId,dataVersion,sha256}]`. **Ответов в плане нет**: головоломку строит клиентский генератор из seed
(языковые категории — по запиненной версии пакета, чтобы у всех игроков ступени слова совпали). Выбор категорий переносим на Kotlin: сортировка по `sha256("lm-daily|1|date|tier|category")`.
Языконезависимые задания совпадают во всех языковых файлах (одинаковые seed), дублируется только 2-килобайтный JSON.

## Ступени (предложение, не утверждено)
Уровни по `Progression.requiredXp` (1→2 = 100 XP): T1 Beginner 1–5, T2 Easy 6–15, T3 Medium 16–30, T4 Hard 31–50, T5 Expert 51–99. Ступень фиксируется при первом открытии дня; повышение уровня в тот же день набор не меняет;
выбрать более лёгкую ступень нельзя (клиент не передаёт ступень, она вычисляется из уровня и фиксируется).

## Lines / Two Dots
Конечные цели из `ArcadeGoals`: Lines — 2–3 линии, Two Dots — 150–250 очков за 20 ходов. Масштабирование по ступеням пока не применено (нужна симуляция).

## Клиент (план доделки)
Загрузка `latest` плана по ступени/языку → кэш в файле → отображение 0/5, ступени, `DailyClock.millisUntilNextDay` → прогресс в DataStore (`DailyProgress`) →
XP через `ProgressRepository.recordAttempt` (уникальный id задания = дедупликация с остальными режимами). Без сети — только ранее загруженный план; локально сгенерированные задания официальными не называть. Фанфары — только Level Up.

## Рейтинги и античит (на будущее, без новых таблиц)
- Справедливое сравнение ступеней: отдельные доски по ступеням либо «процент выполнения + серия дней» (не сырой XP); сумма XP за день нормируется на максимум ступени.
- Серия дней: считать по серверной UTC-дате плана, а не по часам устройства.
- XP клиент не доверен: подтверждённые результаты — через Cloud Function с Firebase App Check, плановый `dailyId` и `puzzleId`, одна награда на `(uid, puzzleId)` (запись в Firestore транзакцией), проверка по seed на сервере (после появления валидаторов).
- Смена системного времени: день определяется серверной датой плана (`validFrom/Until`), сравнение с серверным временем при отправке.
- Бонусы вынесены в конфигурацию (`DAILY_CONFIG`, `DailyConfig`); размеры не утверждены.
